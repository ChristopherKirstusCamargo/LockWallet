# ADR 0003 — BIP-39, SLIP-0010, caminhos e compatibilidade

- **Status:** Aceito — implementado e verificado (Fase A)
- **Data:** 2026-11-19
- **Spec:** LOCK WALLET v2.0 + v2.1 + v2.2 (+ prompt 1.2 do proprietário); ver `docs/errata.md`.

## Contexto
Spec §9, §23.1; v2.1 §3, §8; prompt 1.2 (usuário escolhe 12 ou 24 palavras).

## Decisão
- Implementação própria e independente em `:core:crypto` (`Bip39`, `Slip10Ed25519`) sobre primitivas Bouncy Castle (SHA-256, HMAC-SHA512, PBKDF2, RFC 8032).
- Criação: 12 (padrão) ou 24 palavras (`MnemonicLength.CREATION_CHOICES`). Restauração/LWRP: 12/15/18/21/24.
- Somente lista inglesa (SHA-256 fixado no código). Sem passphrase no MVP (API de passphrase é `internal`, só para vetores Trezor).
- **Entrada canônica:** o core aceita apenas palavras minúsculas ASCII separadas por um espaço. Para essa entrada NFKD é identidade, então os bytes PBKDF2 = ASCII, sem criar `String` do segredo. A UI é responsável por tolerância (maiúsculas, espaços) e entrega a forma canônica. *Desvio documentado*: o core não chama `Normalizer` — equivalente para a lista inglesa e evita cópias do segredo em `String`.
- Checksum obrigatório também para derivar a seed (mais estrito que BIP-39).
- Perfis numéricos: `0x01` PRIMARY `m/44'/501'/i'/0'`; `0x02` LEGACY_LEDGER `m/44'/501'/i'` (rotulado, nunca misturado). Todos os níveis hardened; `i` ∈ [0, 2^31).

## Alternativas rejeitadas
Biblioteca BIP-39/HD pronta (dependência extra e menos controle de memória); aceitar entrada não canônica no core (normalização silenciosa).

## Consequências
Endereços reproduzíveis por outras carteiras que usam os mesmos caminhos.

## Risco residual
Descoberta 0–19/5 vazios é heurística (v2.1 §8).

## Evidência
Vetores Trezor (24), SLIP-0010 oficiais TV1/TV2, spec §23.1 (3 endereços), 15 vetores de oracle (5 tamanhos × 2 perfis × 4 índices incl. 2^31−1) — `docs/fixtures.md`.
