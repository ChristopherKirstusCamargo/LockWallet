# ADR 0004 — LWRP binário v1, KDF, AAD e compatibilidade futura

- **Status:** Aceito — estrutura (Fase A) e cifra (Fase B, `LwrpCipher`) implementadas
- **Data:** 2026-11-19
- **Spec:** LOCK WALLET v2.0 + v2.1 + v2.2 (+ prompt 1.2 do proprietário); ver `docs/errata.md`.

## Contexto
Spec §10, v2.1 §2–3; revisão externa: janela 62 B–1 MiB contradiz payload fixo.

## Decisão
Cabeçalho 46 B (magic `LWRP`, v1, KDF 0x01 = Argon2id v0x13/32 B, salt 16, m/t/p u32 BE, nonce 12); AAD = os 46 bytes. Payload 48 B (`LWPL`) + material. **Tamanho de arquivo exato** = 110 + material_length ∈ {126,130,134,138,142,174}; validado antes de qualquer KDF (errata E-01). Perfis m/t/p por allowlist exata (`COMPAT_V1`). account_index ≥ 2^31 rejeitado. Flags ≠ 0 rejeitadas. Senha: NFC + UTF-8, 16–256 bytes; sugerido gerar 8 palavras (88 bits). Erros estruturais pós-decifragem são mapeados na UI para a mesma mensagem genérica.

## Alternativas rejeitadas
JSON; parâmetros KDF arbitrários; tamanho máximo genérico de 1 MiB.

## Consequências
Formato futuro ⇒ nova versão/KDF id; leitores v1 recusam.

## Risco residual
Senha fraca continua atacável offline.

## Evidência
Fixture `lwrp-v1-structure.json` (implementação Python `struct` independente).

## Teste
`LwrpCipherTest` (3 arquivos cifrados byte a byte × libsodium/pycryptodome, NFD→NFC, senha errada ≡ adulteração, regras de senha), exportação com verificação após gravar via SAF (`RecoveryDocumentIo`: grava, lê de volta, compara, reabre com a senha, confere a pubkey; só VERIFIED conta). `LwrpStructureTest` (11 positivos byte a byte, 24 negativos de payload, 36 de arquivo).

## Condição para reabrir
Necessidade de passphrase/multi-conta no pacote.
